## Active Plan Constraints

- Preserve the existing formal API curriculum. Reorder and progressively reveal
  material rather than removing the depth that already exists.
- Design first for non-developers in marketing, HR, accounting, finance, and
  similar teams who have heard the term API but do not yet think in terms of
  software systems or data abstractions.
- The opening must explain why APIs are useful and when they fit before teaching
  manual requests, JSON, authentication, code, or API construction.
- Help visitors collaborate with development teams. Do not frame becoming an API
  specialist or building every integration themselves as the primary outcome.
- Keep English and Spanish translation keys and meaning in sync.
- Use Nano Banana Pro for the final primary hook illustration, Flash for the
  main supporting explanation, and Lite for small use-case illustrations.
- Generated images must contain no text, logos, fake product interfaces, or
  essential information that is unavailable in HTML.
- Do not commit, push, or perform other git actions without asking the user.
